# PinPlan Implementation Plan

> For agentic workers: use task-by-task execution, test each functional boundary, and request an independent final code review. Closely coupled core tasks are executed inline.

**Goal:** Deliver the chosen Pico resource planner and prepare the current hackathon submission.
**Architecture:** MoonBit owns pin/resource semantics and search. Node and the browser are thin I/O and display adapters to one JSON API.
**Tech Stack:** MoonBit 0.10.14+, standard library only; Node.js; static HTML/CSS/JS.
**Spec:** ../specs/2026-10-11-pinplan-design.md

## Global Constraints
- Pico GPIO0..22 and GPIO26..28 only; UART/SPI/I2C/PWM.
- Shared I2C/SPI requires explicit matching bus, instance, pins and frequency; CS remains exclusive.
- Distinguish invalid input, proven no solution, and budget exhaustion.
- Independent code and hand-derived test expectations; submission materials excluded from public Git and package.
- No invented user identity, repository URL, test evidence, or official acceptance claim.

## Task 1: Board capability and data model
- [ ] Add public Kind/Device/Assignment/Finding/Report types in types.mbt and Pico signal predicates in board.mbt.
- [ ] First add board_test.mbt: assert UART0 TX GPIO0 valid, GPIO4 invalid; I2C1 SDA GPIO2 valid; GPIO23/29 unavailable; PWM GPIO0 and16 alias slice/channel.
- [ ] Run moon test, observe missing API/behavior failure, implement, rerun.
- [ ] Record the official RP2040 and Pico mapping sources in docs/SOURCES.md and commit the tested deliverable.

## Task 2: Validation and resource conflicts
- [ ] Add validate_test.mbt first: duplicate IDs and unknown signal fail; locked GPIO23 fails; shared I2C GPIO0/1 succeeds; SPI CS reuse fails; PWM alias and differing slice frequencies fail.
- [ ] Implement validate_devices and check_assignments with structured finding codes and involved devices/resources.
- [ ] Run moon test, fix failures against the documented resource model, commit.

## Task 3: Deterministic planning
- [ ] Add solver_test.mbt first for valid mixed peripherals, fixed-pin preservation, impossible locked assignment, zero node budget, and deterministic repeat.
- [ ] Implement deterministic bounded DFS; validate every complete assignment; do not conflate exhausted budget with unsatisfiable.
- [ ] Add exhaustive small PWM/UART reference cases with independent literal capabilities, then run moon test and commit.

## Task 4: JSON boundary and executable demo
- [ ] Add json_test.mbt before decoder: malformed JSON, missing/extra fields, wrong number types, unknown board/kind/mode, negative budget, and incomplete check configuration.
- [ ] Implement run_json(String)->String; invalid input returns structured JSON rather than panicking.
- [ ] Add bridge/main.mbt export and examples/main.mbt runnable example. Build JS and run the same API from Node.
- [ ] Add Node integration tests for CLI solved=0, invalid=2, unsatisfiable=3, limit=4; add fixtures and a script to generate the browser module.

## Task 5: Reviewable browser demo and reproducibility
- [ ] Implement web/index.html using the compiled MoonBit module; fixture presets, findings, pin table and SVG board highlight.
- [ ] Add README, MIT license, source notes and GitHub Actions check/build/test/CLI workflow.
- [ ] Verify browser interactions and all documented commands; obtain an independent review and fix material findings.

## Task 6: Submit with verified evidence

- [ ] Verify public tree excludes proposal and private submission files; verify CI and release package contents.
